# v1.2 Plan: H-1B Selection Odds Lab

## Summary

Build a public-data H-1B selection intelligence layer on top of the v1.1 DOL LCA wage pipeline. The feature should answer:

- How many H-1B registrations were likely selected this year by wage level?
- Which companies, occupations, and locations look strongest under a wage-weighted selection process?
- Given a user's LCA, occupation, location, employer, and wage level, what is the estimated probability of selection?

The product must stay honest: USCIS selection notices and beneficiary-level lottery results are private. Therefore, the dashboard should never claim it knows the exact selected workers or exact picked LCAs. It should present **estimated selections**, **selection odds**, and **confidence ranges** using public DOL LCA data, USCIS aggregate registration statistics, and the wage-weighted lottery rule.

## Product Name

**H-1B Selection Odds Lab**

Placement: directly after the existing **H-1B Wage Intelligence** section in `docs/dashboard.html`.

## Data Truth Boundaries

### What We Can Say

- "This employer filed X certified H-1B LCAs in the cap-season proxy window."
- "These filings correspond to Y weighted lottery entries under Level I-IV assumptions."
- "Given the public aggregate USCIS selected-registration count, this group would be expected to receive approximately Z selections if the modeled pool reflects the registration pool."
- "For this user profile, the estimated selection probability is P%, with a likely range of L-H%."

### What We Cannot Say

- "These exact workers were picked."
- "This exact LCA was selected."
- "This company got exactly N selected beneficiaries."
- "This person will be selected."

### Required Dashboard Caveat

Every Selection Odds view must show:

> This is a public-data estimate, not an official USCIS lottery result. USCIS does not publish selected beneficiaries by employer, occupation, location, or wage level. LCA certification does not prove lottery selection or petition approval.

## Cap-Subject Classifier

The classifier should be explainable and conservative. It is not trying to prove cap-subject status; it is estimating likelihood.

Positive signals:

- `CASE_STATUS = Certified`
- `VISA_CLASS = H-1B`
- `NEW_EMPLOYMENT > 0`
- `BEGIN_DATE` near the H-1B cap start window, especially September 1 through December 31 of the selection year
- `TOTAL_WORKER_POSITIONS > 0`
- Plausible annualized offered wage
- Private-sector employer patterns

Negative signals:

- `CONTINUED_EMPLOYMENT > 0` with no new employment
- `AMENDED_PETITION > 0` with no new employment
- `CHANGE_EMPLOYER > 0` without new employment
- Cap-exempt-like employer names such as universities, colleges, nonprofit research institutes, and some hospitals
- Begin dates far away from the October 1 cap start window
- Implausible wage flags

Suggested first-pass formula:

```text
score = 0
+ 0.35 if new_employment > 0
+ 0.25 if begin_date between Sep 1 and Dec 31
+ 0.10 if begin_date between Apr 1 and Aug 31
+ 0.10 if wage_plausibility_flag = PLAUSIBLE
+ 0.10 if employer does not match cap_exempt_pattern
+ 0.10 if total_worker_positions > 0
- 0.30 if continued_employment > 0 and new_employment = 0
- 0.25 if amended_petition > 0 and new_employment = 0
- 0.25 if change_employer > 0 and new_employment = 0
- 0.35 if employer matches strong cap_exempt_pattern
```

Clamp to `0.0 <= score <= 1.0`.

## Wage Weighting

Use the DOL LCA wage level:

```text
Level I   = 1 entry
Level II  = 2 entries
Level III = 3 entries
Level IV  = 4 entries
Unknown   = scenario-dependent
```

Unknown wage level handling:

- Baseline scenario: exclude Unknown from probability calculator, include in dashboard as "Unknown".
- Sensitivity scenario: assign Unknown the median known wage-level weight for same SOC/location when there is enough data.

## Core Probability Model

### Deterministic Expected Value

```text
effective_positions = proxy_worker_positions * cap_subject_score
weighted_entries = effective_positions * wage_weight
total_weighted_entries = SUM(weighted_entries)

expected_selections_for_group =
  selected_registrations * group_weighted_entries / total_weighted_entries

expected_selection_rate =
  expected_selections_for_group / group_effective_positions
```

### Individual Profile Estimate

Use weighted sampling without replacement approximation:

```text
base_probability =
  1 - exp(-(selected_registrations * wage_weight) / total_weighted_entries)
```

Then adjust for classifier confidence:

```text
estimated_probability =
  base_probability * cap_subject_score_adjustment * masters_cap_adjustment
```

Do not overfit the first release. Keep the first model transparent.

### Masters Cap Adjustment

v1.2 should support `masters_cap_eligible` as:

```text
Yes
No
Unknown
```

Initial adjustment:

- `No`: regular weighted estimate only.
- `Unknown`: blended estimate, defaulting to regular-only unless user selects yes.
- `Yes`: show a separate "advanced degree eligible" scenario.

Because the public LCA file does not identify beneficiary education, this must remain user-supplied or scenario-based.

## Monte Carlo Simulation

Run repeated weighted draws to create uncertainty intervals:

```text
for simulation in 1..N:
  draw selected_registrations positions from weighted pool
  probability proportional to wage_weight * cap_subject_score
  aggregate selections by wage level, employer, SOC, location
```

Default:

```text
N = 10,000 simulations
```

Outputs:

- Expected selections
- Median selections
- 5th percentile
- 95th percentile
- Selection rate range
- Confidence score

## Confidence Score

Each estimate should carry a confidence score.

Inputs:

- Comparable case count
- Comparable effective positions
- Wage level known vs unknown
- Cap-subject score strength
- Latest DOL quarter available
- Specificity of lookup bucket

Example scoring:

```text
High:
  50+ comparable cases, known wage level, high cap-subject score

Medium:
  10-49 comparable cases or mixed classifier evidence

Low:
  fewer than 10 comparable cases, unknown wage level, or broad fallback bucket
```

## Static Dashboard Data Strategy

The dashboard should stay self-contained.

Do not embed row-level LCA data into `docs/dashboard.html`; it will get too large. Instead embed:

- Top N employer estimates
- Top N occupation estimates
- Top N location estimates
- Wage-level summaries
- Compact profile probability index
- Optional LCA lookup index for case number prefill, capped to cap-season proxy rows only

Target dashboard size:

```text
Under 3 MB
```

If the probability index is too large:

- Compress keys into short codes.
- Limit city-level grid to top locations.
- Use fallback national SOC/wage-level grid for long tail.

## Test Plan

### Data Validation

- Confirm only H-1B LCA rows enter the model.
- Confirm all included wages are plausible or explicitly flagged.
- Confirm wage levels are only Level I, II, III, IV, or Unknown.
- Confirm `weighted_entries = effective_positions * wage_weight`.
- Confirm total modeled effective positions and weighted entries are non-zero.

### Model Validation

- Sum of expected selections across wage levels should equal selected registrations within rounding tolerance.
- Sum of expected selections across employer groups should equal selected registrations within rounding tolerance when using complete employer universe.
- Simulation median should be close to deterministic expected value for large groups.
- p05 <= p50 <= p95 for all simulated outputs.
- Confidence score should drop for sparse groups.

### Dashboard Validation

- New section renders after H-1B Wage Intelligence.
- Calculator works with an exact LCA case number.
- Calculator works without LCA case number using manual fields.
- Long employer and SOC names do not overflow UI.
- Static HTML remains under target size.
- Existing V7 and v1.1 charts still render.

## Risks

| Risk | Why It Matters | Mitigation |
|------|----------------|------------|
| Public data does not include selected beneficiaries | Users could over-trust estimates | Caveats, confidence ranges, no exact-pick language |
| LCA rows do not map 1:1 to registrations | One LCA can cover multiple workers; some registrations may not have certified LCAs yet | Use proxy positions, classifier score, and uncertainty bands |
| Cap-exempt employers distort the pool | Universities/research/hospitals may file LCAs outside the cap | Cap-subject classifier and visible classifier reasons |
| FY2026 Q1 is early | Later cap-season filings may be missing | Support quarterly refresh with `--quarter latest` |
| Unknown wage levels | Selection weight may be missing | Exclude from calculator baseline; include sensitivity scenario |
| Static HTML size grows too much | GitHub Pages remains static | Embed compact summary/index data only |
